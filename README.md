# 定时任务抖动与平滑（从 0 实现）

仓库里只有本说明、`samples/**` 与 `.gitignore`：库、命令行入口、页面与测试都从零写。`samples/notes.md`
是现场记录，不参与判定。

## 1. 范围

交付物（仓库根，Python 3.13 标准库）：

```text
python -m jitter plan <任务文件> <排布文件>
python -m jitter page <任务文件> <页面文件>
```

`jitter/` 是库加命令行入口；`plan` 排出每个任务的每次触发并写排布文件；`page` 用同一份排布结果写一个
自包含 HTML（数据内联，双击即开）；`tests/` 放 `unittest` 用例，只读 `samples/`。

做：整数秒时间轴上的确定性错峰——抖动窗口、同一任务最小间隔、窗口重叠时的推后、失败重试、峰值并发
上限、十万级任务、单文件页面。
不做：不接真实调度器、不下发任务、不做持久化与断点续排、不做时区与日历；
不引第三方依赖、不联网、不加构建；非法输入不做容错（样例保证合法，遇到非法输入报错退出即可）；页面
不做编辑与交互重排。

## 2. 口径与公式

时间轴是整数秒，从 0 起；任务文件给出排布区间 `[0, horizon)`。

**任务**：`id`（小写字母、数字与连字符）、`first`（首次期望触发时刻）、`period`（周期秒）、`prio`
（优先级 1/2/3，1 最高）、`dur`（每次占用秒数）。第 k 次期望触发（k 从 0 起）
`E(k) = first + k * period`，只排 `E(k) < horizon` 的那些。

**抖动窗口**（只许晚、不许早）：实际时刻 `A(k)` 落在 `[E(k), E(k) + W]`，`W` 按优先级取值：prio 1 →
10 秒，prio 2 → 60 秒，prio 3 → 300 秒。

**同一任务最小间隔**：相邻两次正常触发的实际间隔 ≥ `G = ceil(period / 2)`（窗口比周期大时两拍重叠，
靠这条下限拉开）；同一任务（含重试）相邻事件至少隔 1 秒。

**确定性散列**（不用随机数，两次运行必须逐位相同）：

```text
key = seed|id|k|j    # 竖线连接；j = 0 是正常触发，j >= 1 是第 j 次重试尝试
h   = FNV-1a-64（key 的 UTF-8 字节）：初值 14695981039346656037，乘子 1099511628211，每步 mod 2^64
z   = h
z   = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9 mod 2^64
z   = (z ^ (z >> 27)) * 0x94D049BB133111EB mod 2^64
z   = z ^ (z >> 31)
抖动 = z mod (span + 1)    # 取 0..span 的整数秒
```

**失败重试**：`fail <id> <k>` 标记第 k 次正常触发的首次尝试失败；`retry <id> <attempts> <backoff>`
给出重试次数与退避。第 j 次重试（j = 1..attempts）的基准 `b = A(k) + j * backoff`，实际时刻落在
`[b, b + min(W, backoff - 1)]`：重试也蹭抖动，但抖动上限不超过 `backoff - 1`，重试之间不会前后颠倒；
重试同样占用并发额度、受上限与推后规则约束。样例保证 `backoff >= 2` 且
`(attempts + 1) * backoff <= G`，所以重试不会越过该任务的下一次正常触发。

**峰值并发**：`cap` 是每个任务文件的峰值并发上限。秒 t 的并发 = 满足 `A <= t < A + dur` 的触发个数
（正常触发与重试一起数）；峰值 = 整个时间轴上的最大值。排完必须 ≤ cap。

## 3. 排布顺序与数据结构

事件分正常触发与重试尝试两类，排布顺序固定：

1. 正常触发：先 prio 1 的全部任务，再 prio 2，再 prio 3；同一轮内按（`E(k)`，id 码点序，k）升序。
2. 重试尝试：同样按优先级分轮；同一轮内按（基准 `b`，id 码点序，k，j）升序。都在正常触发之后。

每个事件有首选下界 `lo` 与上界 `hi`：正常触发 `lo = E(k) + 抖动(span = W)`、`hi = E(k) + W`；
重试 `lo = b + 抖动(span = min(W, backoff - 1))`、`hi = b + span`。逐个放置：从 `t = max(lo, 下界)`
起向后取最早的整数秒 `t <= hi`，使 `[t, t + dur)` 的每一秒并发都 `< cap`；窗口内放不下就报错退出
（样例保证放得下）。下界：正常触发取同一任务上一次正常触发的实际时刻 + G（k = 0 没有下界）；重试取
同一任务上一条事件的实际时刻 + 1。

数据结构：事件表（`lo`、`hi`、`dur`、排序键）、逐秒并发计数（长度 = 时间轴跨度）、每任务上次事件
时刻。扫描范围不超过窗口大小，十万级批次要在第 5 节的预算内跑完。

## 4. 输入输出与文件格式

本节文件一律 UTF-8、`\n`、末行有换行；空行与 `#` 开头的行忽略。

**4.1 任务文件** `samples/tasks/<名>.tasks`：前三个有效行依次是 `seed <整数>`、`horizon <整数>`、
`cap <整数>`；其后每行一条：

```text
task <id> <first> <period> <prio> <dur>
retry <id> <attempts> <backoff>    # 每个任务至多一行
fail <id> <k>                      # 可重复；k 是第 k 次正常触发
```

**4.2 排布文件**：`plan` 的输出，与 `samples/expected/<同名>.out` 逐字节相同。第一行
`peak <峰值> firings <触发数>`；其后每个触发一行 `<秒> <id> <k> <j>`，按（实际时刻，id 码点序，k，j）
升序。

**4.3 页面**：`page` 写一个自包含 HTML（无外部资源、不 fetch，双击即开），内联一份 JSON
（`<script type="application/json" id="plan">`），键固定为：

```text
meta    {seed, horizon, cap, peak, span, tasks, rows}  # span 是并发数组长度，tasks 是任务总数
tasks   画出来的任务 id，按 id 码点序，最多 2000 个
firings [秒, 行号, k, j]，行号是任务在 tasks 里的下标；只含画出来的行，顺序与排布文件一致
conc    长度为 span 的整数数组，conc[t] 是第 t 秒的并发
```

页面要画：① 时间轴；② 每个画出的任务一行，行内点出它的触发点（重试与正常触发样式可区分）；③ 下方并发
曲线（直接用 `conc`），画出 cap 横线，`conc[t] > cap` 的段标红；④ 标题栏写 seed、horizon、cap、peak、
任务总数与画出的行数。位置与数字只能取自 JSON，不许在页面里重算并发或重排触发；配色与交互自定。

## 5. 性能与验收口径

测试机 Windows + Python 3.13 单线程：

1. **环境**：只用标准库；无网络、无构建、无第三方依赖；命令在仓库根直接跑。
2. **期望**：每个 `plan` 的输出与 `samples/expected/<同名>.out` 逐字节相同。
3. **约束**：实际时刻落在窗口内；相邻正常触发间隔 ≥ G；同一任务任意两次相邻事件 ≥ 1 秒；峰值 ≤ cap。
4. **预算**：`06-scale-100k`（100 000 个任务）端到端 ≤ 20 秒、峰值内存 ≤ 512 MiB；其余样例每个 ≤ 2 秒；
   页面（≤ 2000 行）≤ 2 秒。
5. **确定性**：同一输入跑两遍逐字节相同，换 `PYTHONHASHSEED` 也一样；页面同样。
6. **页面**：结构齐全、无外部资源；手改内联 JSON 里的 `conc` 或 `cap` 再刷新，页面跟着变。
7. **测试**：`python -m unittest` 通过，用例只读 `samples/`，只用标准库。
