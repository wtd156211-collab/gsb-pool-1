# 缩进敏感文本解析（从 0 实现）

起始环境只有本说明与 `samples/`：`files/` 是输入文本，`expected/` 是一一对应的期望结果，`notes.md` 是现场记录；解析器、入口与 HTML 报告从 0 写。

## 一、范围

**做**：仓库根目录的单文件脚本 `main.py`，只用 Python 3.13 标准库，不加依赖与构建步骤——把缩进敏感的文本解析成树，在 stdout 输出规范文本，可另写一份自包含 HTML 报告。入口固定：

```
python main.py [--html <输出路径>] <输入文件> [<输入文件>…]
```

**不做**：不认 YAML 那一套（锚点、引用、转义、流式集合、`---` 分隔一律不认）；不做类型推断（标量都是字符串）；不做多文档与增量解析，不联网，不改写输入；除命令行与 I/O 错误外不抛异常。

## 二、口径与公式

**行与缩进**：按 `\n` 切分，行尾 `\r` 算行终止符，文件末尾的换行不产生空行；剥掉行尾空白后行号从 1 起。行首连续空白是缩进，折算宽度 `w = 空格数 + 4 × 制表符数`，缩进单位 4 列，层深 `d = w / 4`；制表符与空格**允许混用**，只要折算宽度对得上；**不允许跳级**，一次最多深 1 级。列号按 Unicode 码点从 1 起算，取首个非空白字符的位置。

**空行与注释行**：剥掉行尾空白后为空的行不产生节点、不校验缩进；首个非空白字符是 `#` 的行（块文本内部除外）不产生节点、不改层级，但缩进要合规——`w` 是 4 的整数倍且 `d ≤ 当前层深 + 1`，否则报 `E_COMMENT_INDENT`。

**行形式**（缩进之后的部分，都不匹配就是 `E_SYNTAX`）：

| 形式 | 写法 | 口径 |
| --- | --- | --- |
| 映射条目 | `键:` 或 `键: 值` | 键是 `[A-Za-z_][A-Za-z0-9_-]*`，`:` 紧跟键，其后是空白或行尾；值是其后文本去掉首尾空白 |
| 块文本 | `键: \|` | 值恰好是 `\|` 时进入块文本；`- \|` 不算，是普通标量 |
| 列表项 | `-` 或 `- 内容` | `-` 后是空白或行尾；内容是其后文本去掉首尾空白 |

**块文本内的缩进**：键行缩进 `b` 列，内容基准 `b + 4` 列。其后每行按行首空白逐字符消耗到消耗满基准，剩余部分原样保留——更深的缩进照留——各行用 `\n` 连接，空行保留成空内容行。遇到消耗不满基准的非空行则块结束，该行按普通行继续解析，文件结束同样结束。块可以零行，值为空串。

**值与容器**：值为空的条目（`键:`、`-`）先算未定，之后出现更深缩进的行就成容器，否则算空标量（值空串）。已定标量又拿到子节点报 `E_SCALAR_CHILD`，值作废、改按容器处理。非根容器下的子条目必须同类，混用报 `E_CHILD_KIND_MIX`，该行仍按自身类型保留。重复键允许，按出现顺序保留。带错误的行只要还能成节点，就按纠偏后的层深照常解析。

**容错上限**：单文件最多记 20 条错误，记满立刻停止解析该文件并追加一条 `E_LIMIT`。

| 错误码 | 触发 | 容错 | 错误行的原因文案 |
| --- | --- | --- | --- |
| `E_INDENT_WIDTH` | `w % 4 != 0` | 取 `d = w // 4`，不再判跳级 | 缩进宽度 {w} 不是 4 的整数倍 |
| `E_INDENT_JUMP` | `d > 当前层深 + 1` | 只算深 1 级 | 相对当前层级一次深入 {n} 级 |
| `E_COMMENT_INDENT` | 注释缩进不合规 | 丢掉该行，层级不变 | 注释缩进宽度 {w} 不在当前层级范围内 |
| `E_SYNTAX` | 行不属于任何形式 | 丢掉该行，层级不变 | 行不符合映射条目、列表项或注释的形式 |
| `E_SCALAR_CHILD` | 标量又拿到子节点 | 值作废，改按容器 | 标量条目不能有子节点 |
| `E_CHILD_KIND_MIX` | 同一容器混用两类子条目 | 该行仍保留 | 同一容器内混用映射条目与列表项 |
| `E_LIMIT` | 错误数到 20 | 停止解析该文件 | 错误数达到上限 20，停止解析 |

一行最多记一条错误：注释行只报 `E_COMMENT_INDENT`，其余行按上表从上往下取第一条。

## 三、状态机与数据结构

节点四个字段：种类（映射条目 / 列表项 / 根）、键、值（未定 / 已定）、子节点表，另记已见子类；根是空容器，层深 -1。

解析状态是一条节点栈（根 + 当前路径），栈顶是当前节点，当前层深 = 栈长 − 2。每行定出纠偏后的层深 `d`，走三条之一：

- `d = 当前层深 + 1`：挂到栈顶下（栈顶是已定标量就先报 `E_SCALAR_CHILD`）。
- `d = 当前层深`：与栈顶同级，挂到栈顶的父节点下，替换栈顶。
- `d < 当前层深`：弹栈到层深 `d`，再按同级处理。

块文本行不进状态机，直接进当前值。

**树形输出**：每节点一行，行首 `2 × 层深` 个空格（顶层条目层深 0）；映射条目写 `键:`、列表项写 `-`，标量再接一个空格和值字面量（`json.dumps(值, ensure_ascii=False)` 的结果），容器不接，空标量写 `""`。

## 四、输入输出与文件格式

全部 UTF-8、LF 换行，stdout 也是 UTF-8 字节，路径按命令行原文。规范文本：

```
# TREE
# <输入文件路径>
<树形输出…>
# ERRORS
# <输入文件路径>
<行号>:<列号>: <错误码>: <原因>
```

按命令行顺序逐文件写，两段里每个文件都有 `# <路径>` 节头（没有错误也留）；错误按文件顺序、行号、列号升序，原因文案用前面错误码表最后一列。前缀的行号列号就是出错行的位置，`E_LIMIT` 取停止时的行号、列号 0。退出码 0 = 正常完成（含报出错误行），1 = 参数或 I/O 错误。

**HTML 报告**（给了 `--html` 才写）：单个完整 HTML 文档，双击能开，样式与数据内联，一个外部引用都不许有（`<link`、`<script`、`http://`、`https://`、`file://` 都不出现）。必须含 `<pre id="tree">` 与 `<pre id="errors">`，其中文本（实体反转义后）与上面两段逐字符相同，只把 `&`、`<`、`>` 写成实体。

## 五、性能与验收口径

- 时间：单文件 ≥ 5 万行（≥ 1 MiB）时，解析 + 输出 + 写 HTML ≤ 5 秒（单进程单线程）。
- 内存：额外峰值 ≤ 256 MiB，逐行读，别整文件复制几份。
- 验收：① 只用标准库、无构建步骤，`python main.py …` 直接可跑；② 逐个单文件跑 `samples/files/<名>.txt`，stdout 里 `# TREE` 与 `# ERRORS` 之间的内容与 `samples/expected/<名>.tree.txt` 逐字节相同，`# ERRORS` 之后与 `<名>.errors.txt` 逐字节相同（UTF-8、LF、末尾一个换行）；③ HTML 的两个 `<pre>` 反转义后与这两段逐字符相同、无外部引用；④ 输入不被改写，同一输入跑两遍结果逐字节相同。

## 六、样例说明

| 样例 | 看点 | 错误 |
| --- | --- | --- |
| basic | 键值、嵌套、列表、块文本、注释 | 0 |
| mixed_tabs | 制表符与空格混用：同层宽度都是 4 合法，`空格 + 制表符` = 5 | 1 条 `E_INDENT_WIDTH` |
| jump | 跳级缩进，按只深 1 级继续解析 | 1 条 `E_INDENT_JUMP` |
| block | 块文本里的更深缩进、块内 `#` 行与空行 | 0 |
| comments | 注释缩进超出当前层级、宽度不是 4 的倍数 | 2 条 `E_COMMENT_INDENT` |
| trailing_ws | 键行、值行、列表项、块文本、注释都带行尾空白 | 0 |
| errors | 标量又拿到子节点、混用两类子条目、行形式错 | 4 条，三种码 |

`files/<名>.txt` 与 `expected/<名>.tree.txt`、`<名>.errors.txt` 一一对应；`notes.md` 是现场记录，不是样例。
