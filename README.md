# 最小二乘拟合（从 0 实现）

起始环境里只有这份说明、`samples/**` 与 `.gitignore`，没有实现代码，程序要新写。Python 3.13，只用标准库，不加依赖、不加构建步骤。

## 1. 范围

在仓库根目录写单文件程序 `fitlib.py`（引擎与命令行入口合一）：

```
python3 fitlib.py <点文件> <报告.html>
```

流式读点，对同一批点分别做直线与二次曲线的最小二乘拟合，向标准输出打印规范摘要，并写出一份可离线打开的自包含 HTML 报告；报告路径的父目录不存在时自行创建。参数个数不对、文件打不开、某行读不动、点数少于 3、互不相同的 x 少于 3 时，向 stderr 打印一行以 `error:` 开头的说明，退出码 2，不写报告；正常结束退出码 0。自测用 unittest（标准库）。

交付时报告按 `var/fit.html` 生成即可（`var/` 已在 `.gitignore` 里）。

明确不做的事：

- 只做这两种模型：直线的 `a`、`b`，二次曲线的 `c2`、`c1`、`c0`；不做升阶、正则化、加权、稳健拟合、广义线性模型；
- 不做异常点剔除后的重拟合：标出来就行，拟合始终用全部点；
- 不引第三方库与外部资源（CDN、字体、图片、网络请求），不写构建脚本；
- 不提供交互界面、批量模式、导出开关；
- 不允许把点一次性读进内存（见第 5 节）。

## 2. 口径与公式

- 点为 `(x_i, y_i)`，序号按数据行在文件中出现的顺序从 1 计；空行与 `#` 注释不算。
- 直线 `y = a·x + b`，二次曲线 `y = c2·x² + c1·x + c0`，两个模型各自独立做最小二乘：`r_i = y_i − ŷ_i`，最小化 `Σ r_i²`。
- 残差统计（每个模型一份）：`n` 点数、`sse = Σ r_i²`、`rmse = sqrt(sse/n)`、`maxabs = max|r_i|`。残差要在与求解同一套中心化坐标里求值，别把大系数展开回原坐标再相减。
- 异常点标记：阈值 `τ = 3 × rmse`（该模型自己的 rmse，全部点一次算定，不迭代剔除）；点 i 是异常点当且仅当 `|r_i| > τ` 且 `|r_i| > 1e-9`（后一条挡住零残差数据里的数值噪声）；清单按序号升序，两个模型各自一份。
- 数值稳定要求：判定基准是精确算术下的最小二乘解。量级悬殊与近共线的样例就是为这条准备的：直接在 float64 下解原始数据的正规方程会掉出容差。中心化、列缩放、正交化（如 Givens/Householder 旋转）、补偿求和怎么组合不限，但要守住第 5 节全部判定。
- 确定性：不依赖随机数、时钟、locale、哈希随机化；同一输入连跑两次，摘要与报告逐字节一致。

## 3. 数据结构

流式处理，保留的状态与点数无关；允许对输入文件多次顺序扫描（求稳的做法通常要多扫几遍），每遍只带常数级状态：

- 第一遍：点数、x 与 y 的最小/最大值、x 的和，“互不相同的 x”凑到 3 个；
- 第二遍：把 x 中心化并缩放到长度 1 附近的 `t = (x − x̄)/s`，在 `t` 上累计两个模型的正规方程系数（直线 2×2，二次曲线 3×3）；
- 解小型方程组得到 `t` 上的系数，换回 `a b` 与 `c2 c1 c0`；
- 第三遍：残差、`sse`、`maxabs`、残差最小/最大值；
- 第四遍：直方图计数、异常点清单、散点槽位代表点；
- 报告一次写全，输入不改写。

## 4. 输入输出与文件格式

一律 UTF-8，报告用 LF 行尾。

### 4.1 点文件 `samples/points/*.txt`

每行一个点 `x y`，空白分隔的十进制数（可带正负号、小数点、指数）；空行和 `#` 开头的行忽略，行首尾空白忽略；其它形态、非有限数（`nan`、`inf`）都算非法输入。

### 4.2 规范摘要（标准输出，也是报告里的 `#summary`）

```
format 1
n <点数>
line <a> <b>
quad <c2> <c1> <c0>
stats line <n> <sse> <rmse> <maxabs>
stats quad <n> <sse> <rmse> <maxabs>
outliers line <k> <序号…>
outliers quad <k> <序号…>
plot <槽位数>
```

行序固定；参数与统计量写成 `format(v, ".12g")`；序号与计数是十进制整数，`outliers` 行 `k` 后面跟 `k` 个升序序号。

### 4.3 报告 `fit.html`（单文件、无外部引用、不依赖脚本）

- `<pre id="summary">…</pre>`：与标准输出逐字符相同；
- `<pre id="resid-hist">…</pre>`：两行 `hist line c1 … c10`、`hist quad c1 … c10`；把该模型的 [残差最小, 残差最大] 等宽分 10 段，第 k 段为 `[min+(k−1)w, min+kw)`（最后一段右端闭合，最小值等于最大值时全记入第 1 段）；每行 10 个非负整数，和等于 `n`；
- `<svg id="fit-plot" viewBox="0 0 960 540">…</svg>`：两条 `<polyline class="curve" data-model="line|quad" fill="none" stroke-width="2">`，各 401 个顶点（`k = 0…400`，`x_k = xmin + (xmax−xmin)·k/400`，`y_k` 由该模型算出，坐标写成 `format(v, ".3f")`）；散点把 `[xmin, xmax]` 等分 2000 个槽（`w = (xmax−xmin)/2000`，第 b 槽 `[xmin+bw, xmin+(b+1)w)`，最后一槽右端闭合），每个非空槽取序号最小的点，画 `<circle class="pt" data-i="<序号>" cx="…" cy="…" r="2"/>`，按槽号升序；
- 坐标映射：`px = 40 + (x−xmin)/(xmax−xmin)·880`、`py = 500 − (y−ylo)/(yhi−ylo)·460`；`ylo`/`yhi` 取数据 y 与两条曲线 401 个采样值合起来的最小/最大值；
- 其余样式自定，数据必须直接写进 HTML 文本，不执行脚本也能核对。

### 4.4 期望文件 `samples/expected/*.txt`

与点文件同名；含一行 `tol <atol> <rtol> <rtol_maxabs>`，其余行与 4.2 同格式（允许 `#` 注释行），数值至少 15 位有效数字。本仓库统一取 `atol = 1e-9`、`rtol = 1e-6`、`rtol_maxabs = 1e-3`。

## 5. 性能与验收口径

预算（Python 3.13、单线程、冷启动计入、同一台机器）：`08-huge`（100 万点，约 14 MiB）单次运行含报告生成不超过 30 秒，峰值常驻内存不超过 64 MiB，报告不超过 512 KiB；内存不随点数增长；其余样例秒级完成。

判定：

1. 逐个样例运行 `python3 fitlib.py samples/points/<name>.txt var/<name>.html`，退出码 0；
2. 参数与 `sse`、`rmse` 满足 `|got − expected| ≤ atol + rtol·|expected|`，`maxabs` 用 `rtol_maxabs`；`n`、异常点序号、`plot` 计数完全相等；
3. 报告 `#summary` 与标准输出一致；`#resid-hist` 每行 10 个整数、和等于 `n`；圆点数等于 `plot`；两条曲线各 401 个顶点；页面无外部引用；
4. 同一输入连跑两次，摘要与报告逐字节一致；
5. 预算在 `08-huge` 上达标，且只依赖标准库；
6. 不得读取 `samples/expected/**` 参与判定，不得按样例名、坐标或点数特判。

## 6. 样例说明

| 样例 | 场景 | 看什么 |
| --- | --- | --- |
| `01-line-exact` | 完美拟合（直线） | 40 个点精确落在直线上，两个模型零残差 |
| `02-quad-exact` | 完美拟合（二次曲线） | 42 个点精确落在抛物线上，直线模型留下系统性残差 |
| `03-scale-gap` | 量级悬殊 | x 整体偏移到 2^30，偏差与 y 跨五六个数量级，系数从 0.25 到 2.9e17 |
| `04-near-collinear-line` | 近共线（直线） | x 挤在 2^20 附近一小段，斜率对解方程方式很敏感 |
| `05-near-collinear-quad` | 近共线（二次曲线） | 同一段窄窗口上，三列几乎相关 |
| `06-outliers-line` | 含离群点（直线） | 122 个点里 4 个明显偏离，两个模型的清单一致 |
| `07-outliers-quad` | 含离群点（二次曲线） | 130 个点里 4 个明显偏离，直线模型的清单为空 |
| `08-huge` | 点数极大 | 100 万个点，流式处理与内存预算的基准 |

每组点对应 `samples/expected/` 的同名文件；`samples/notes.md` 是现场记录。
