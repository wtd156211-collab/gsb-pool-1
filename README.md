# 短码生成与解析（从 0 实现）

## 一、范围

要交付三样东西：一个只用 Python 3.13 标准库的短码引擎（库 + 命令行入口）、
针对 `samples/` 里各批编号的逐行结果，以及 `web/` 下一个静态页面。
引擎把编号编成定长短码，也能把短码解回编号；页面把一批编号的短码排成网格，
退避过的条目标黄，非法短码单独一栏并写明原因。

明确不做：不做短链服务与跳转、不落地页、不做访问统计；不保存编号与短码的对应关系，
不读写数据库；不做老系统历史短码的兼容与迁移（老码一律拒绝）；不做并发分配与分布式发号；
不引入任何第三方依赖，不加构建步骤，页面不引外链资源。

## 二、字符集、长度与容量

字母表固定 32 个大写字符：

`0123456789ABCDEFGHJKMNPQRSTVWXYZ`

必须避开的形近字符是字母 `I`、`L`、`O`、`U` 以及全部小写字母，它们都不在字母表里。
数字 `0` 与字母 `O`、数字 `1` 与字母 `I`/`L` 的混淆，靠字母表里没有 `O`、`I`、`L` 来消除；
大小写不做归一化，出现小写也按非法字符处理。

短码 = 载荷位 + 1 位校验位，总长 L 只能取 6、7、8，默认 6。载荷占 L-1 位，
每位 5 比特，容量 `C(L) = 32^(L-1)`，编号 n 必须满足 `0 <= n < C(L)`：

| L | 容量 C(L) | 说明 |
| --- | --- | --- |
| 6 | 33,554,432 | 千万级；百万级样例用它 |
| 7 | 1,073,741,824 | 十亿级 |
| 8 | 34,359,738,368 | 三百亿级 |

长度是取舍点：5 位码放不下 1,048,576 条（上百万条就顶到天花板），
6 位码够 3355 万条，7 位码够 10.7 亿条；长一位更安全，念和抄都更费劲。

## 三、编码口径

载荷：把编号 n 当 5P 位无符号整数（P = L-1，w = 5P），做一次可逆混淆

```
x = (((n XOR M) * K) + S) mod 2^w
```

其中 M = 0x9E3779B9、K = 0x85EBCA6B、S = 0xC2B2AE35，三个常量都先按位与 `2^w - 1` 再用；
K 是奇数，在模 `2^w` 下必有逆元。解码走逆运算：

```
n = ((((x - S) mod 2^w) * K^-1) mod 2^w) XOR M
```

载荷字符：x 从高位到低位切 5 比特一组，共 P 组，每组取字母表对应下标的字符。

校验位：记载荷第 i 个字符在字母表中的下标为 v(i)，校验值
`c = (sum(v(i) * (2i + 1)) for i = 0..P-1) mod 32`，校验字符取字母表第 c 个字符，
拼在载荷之后。权重全是奇数、模 32 可逆，所以任意单字符替换一定被发现；
相邻两位互换在取值差不为 16 时会被发现。

退避：优先用能放下的最短长度。目标长度放不下编号时，按 L+1、L+2 依次升位，
每升一级记 1 轮退避，最多升到 --max-length（默认 8）；到上限仍放不下就拒绝，
原因码 `E_CAPACITY`。任何情况下都不许取模回绕，也不许悄悄换一个编号。

批量：按输入文件的行顺序逐行处理，结果与输入一一对应。同一条编号的短码只由编号和
初始长度决定，与批次内容、处理顺序、历史状态无关，重复编号得到相同短码；处理过程
只允许常数级状态，不许缓存整批编号或短码。编码不得依赖随机数、时间与哈希种子：
同一份输入连续跑两遍，输出必须逐字节相同（UTF-8、LF、无 BOM）。

## 四、解析口径

判定顺序固定，先命中先返回，用来决定原因码：

1. 长度不在 6、7、8 之内 → `E_LENGTH`
2. 含字母表之外的字符（`I`、`L`、`O`、`U`、小写、空格、连字符等）→ `E_CHARSET`
3. 重算校验值与末位字符对不上 → `E_CHECK`
4. 以上都过 → 返回编号与短码长度

被拒绝的短码不返回任何编号，不做大小写归一化、不做形近字符替换、不做模糊匹配。
编码侧还会用到 `E_ID`（编号不是非负十进制整数）与 `E_CAPACITY`（超出长度上限）。

## 五、输入输出与文件格式

命令行（模块入口，示例含义为准）：

```
python -m shortcode batch --ids <编号文件> --length 6 [--max-length 8] --out <TSV>
python -m shortcode check --codes <短码文件> --out <TSV>
python -m shortcode page  --ids <编号文件> --length 6 --out <目录>
```

- `batch` 输出表头 `id	code	decoded	backoff`，每行对应输入的一行，顺序一致；`decoded`
  是同一行短码解析回来的编号，`backoff` 是退避轮次（0、1、2…）。
- `check` 输出表头 `code	result`，`result` 为 `ok:<编号>` 或原因码；不写别的列。
- `page` 在输出目录生成静态页面（`index.html`，内联 SVG、无外链）；不传 `--out` 时
  默认写 `var/`，仓库不跟踪该目录。

编号文件：UTF-8、LF、每行一个十进制编号，只允许数字、没有前导零与正负号，空行跳过。
短码文件：UTF-8、每行一个短码，原样使用，不去空格、不折叠大小写。
所有输出文件都用 LF 结尾，不带 BOM。

## 六、性能与验收口径

- 吞吐：单进程 `batch` 处理 `samples/ids/04-million.txt`（100 万条）不超过 60 秒，
  含读入与写出；实现得当时纯计算应在 10 秒内。
- 内存：峰值内存不随条数增长——100 万条与 128 条两批跑下来，峰值差不超过 32 MB。
- 一致性：同一输入连续跑两遍，输出文件逐字节相同。
- 样例：`samples/expected/*` 四个 TSV 逐行比对必须全中；`samples/bad-codes/*` 每条
  按表中原因码拒绝；每批的冲突数必须是 0。
- 页面：网格里的短码、标黄条目、非法码与原因都必须来自引擎对同一批编号的输出，
  页面离线可打开，不引外部脚本、样式与字体。
- 测试：实现自带的测试用标准库 `unittest`，同样不引第三方框架。

## 七、样例说明

| 素材 | 规模与场景 | 期望 |
| --- | --- | --- |
| `samples/ids/01-sequential.txt` → `samples/expected/01-sequential.tsv` | 128 条，0 起顺序递增 | 6 位码，退避 0 |
| `samples/ids/02-random.txt` → `samples/expected/02-random.tsv` | 512 条，10^8..10^9 随机分布 | 升到 7 位，每条退避 1 |
| `samples/ids/03-nearby.txt` → `samples/expected/03-nearby.tsv` | 256 条，20 亿附近的近邻编号 | 升到 8 位，每条退避 2 |
| `samples/ids/04-million.txt` → `samples/expected/04-million.tsv` | 100 万条，1 起顺序递增 | 6 位码，退避 0 |
| `samples/expected/conflict-rate.txt` | 逐批统计 | 冲突数 0，冲突率上界 0 |
| `samples/bad-codes/length.tsv` | 长度不对 | 全为 `E_LENGTH` |
| `samples/bad-codes/charset.tsv` | 含形近字符、小写、空格、连字符 | 全为 `E_CHARSET` |
| `samples/bad-codes/checksum.tsv` | 校验位被改坏 | 全为 `E_CHECK` |

冲突率的定义是「同一批里两个不同编号落到同一短码的比例」。本口径下载荷是双射、
校验位是载荷的函数，容量内不同编号的短码必不相同，因此冲突率上界是 0；
`conflict-rate.txt` 里的每一列就是按这个定义逐批算出来的。
`samples/notes.md` 是现场记录，只交代背景，不作为口径。
