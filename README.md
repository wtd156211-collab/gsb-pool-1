# 计数器回绕与增量还原（从 0 实现）

起始环境里只有这份说明与 `samples/` 下的序列、期望结果：库、命令行入口、页面与测试都从零写。
`samples/notes.md` 是现场记录，只作背景，口径以本说明为准。

## 1. 范围

**做**：读一批 32 位计数器采样，按设备还原增量序列，把回绕、复位、突降、乱序四类异常标出来，写成
JSONL；再用原生 ES module 页面把原始计数与增量画成上下两条曲线。

```
python -m counterwrap reduce  <序列文件> <结果.jsonl>   # 采样 + 增量 + 异常 + 汇总
python -m counterwrap summary <序列文件> <汇总.jsonl>   # 只写汇总行，给规模样例用
```

- 交付：可 `import` 的库 + 上面两条入口（Python 3.13，只用标准库，测试用 `unittest`）；`web/` 下的静态
  页面（原生 HTML/CSS/ES module，无构建、无依赖）。
- **不做**：不补缺失点、不插值、不平滑；不预测下一个计数；不做 16/64 位计数器与可配置阈值；不做多个
  计数器之间的关联分析；不改写输入；不联网、不建数据库、不做并发；不引第三方依赖、不加构建步骤；
  坏输入只要求退出码 2 加一行 stderr（`samples/` 保证合法）。

## 2. 口径与公式

### 2.1 计数与时刻

- 计数是无符号 32 位整数：`0 ≤ v ≤ 4294967295`，`MOD = 2^32 = 4294967296`。
- 时刻是 UTC 秒级、定长零填充：`YYYY-MM-DDTHH:MM:SSZ`，比较可直接按字符串；同一设备不重复时刻。
- 同一设备的采样在文件里连续成块（块序任意），块内允许乱序；单设备块不超过 20 万点。

### 2.2 增量、回绕、复位与突降（核心取舍）

相邻样本 `prev → next`，模差 `Δ = (next − prev) mod MOD`：

| 条件 | 判定 | 增量 |
| --- | --- | --- |
| `next ≥ prev` | 正常 | `next − prev`：数值上升一律算增量，多大都算 |
| `next < prev`，`Δ < 2^31` | **回绕**：越过 `MOD` 归零后继续 | `Δ` |
| `next < prev`，`Δ ≥ 2^31`，`next = 0` | **复位**：设备重启、计数归零 | 0 |
| `next < prev`，`Δ ≥ 2^31`，`next ≠ 0` | **突降**：计数被回退，原因不明 | 0 |

阈值取半量程 `2^31 = 2147483648` 是写死的取舍：放宽会把复位误判成一次巨大增量，收紧会把真回绕算成
负增量。复位与突降都从 `next` 起以新基线继续，增量记 0，不再回填。

### 2.3 缺失点与乱序

- **缺失点跳过**：不假设固定采样周期；缺掉的采样不补点、不拆增量、不记异常，跨缺口就出一条增量，
  跨度由 `from`/`to` 显出。
- **乱序归位**：增量一律按时刻升序算；一条样本的时刻小于同设备此前已到达样本的最大时刻，就记一条
  `late`（乱序）异常，这条样本照常参与还原。

## 3. 数据结构与处理顺序

每台设备的状态只有：当前块的行、块内最大到达时刻、上一还原值、累计量。逐行读入时先判乱序，块内按
`(时刻, 到达序)` 稳定排序，再顺序推进相邻对；判定只看 `prev`、`next` 与 `Δ`，不看速率也不看间隔。
输出按设备名（ASCII）升序分组，设备之间互不影响。空行忽略；字段数、格式、计数越界算坏输入。

## 4. 输入输出与文件格式

全部 UTF-8、LF 换行。

### 4.1 输入 `samples/series/<名>.csv[.xz]`

每行 `设备,时刻,计数`，无表头、无空格、无引号：

```
dev-a,2026-03-02T00:00:00Z,1000
```

设备名 `[a-z0-9-]{2,16}`；行序即到达顺序。后缀 `.xz` 表示同一内容的 xz 压缩（标准库 `lzma` 流式读，
`09-scale` 就是），其余按纯文本读。

### 4.2 输出 JSONL（紧凑、键序固定、逐字节核对）

每行一个对象，紧凑写法（`,` 与 `:` 后不加空格）、LF 换行、文件末尾留一个换行。`reduce` 写四段，
`summary` 只写第四段：

```
{"t":"sample","dev":"dev-a","ts":"2026-03-02T00:00:00Z","value":1000}
{"t":"increment","dev":"dev-a","from":"2026-03-02T00:00:00Z","to":"2026-03-02T00:01:00Z","delta":12,"kind":"normal"}
{"t":"anomaly","dev":"dev-a","ts":"2026-03-02T00:01:00Z","kind":"wrap","line":4}
{"t":"summary","dev":"dev-a","points":4,"steps":3,"sum_delta":50,"wrap":1,"reset":0,"drop":0,"late":0}
```

- 段序 `sample → increment → anomaly → summary`；段内按设备字典序、再按时刻升序；异常同刻按 `kind`
  字典序；`summary` 每设备一行，最后一行 `dev` 为 `*`，是各设备之和。
- `kind`：增量取 `normal`/`wrap`/`reset`/`drop`，异常多一个 `late`；`line` 是这条异常对应样本在输入
  文件里的行号（从 1 起）；`reset`、`drop` 的 `delta` 记 0。
- `points` 是采样条数，`steps = points − 1` 是增量条数；数字是十进制整数，不用科学计数法。

### 4.3 页面 `web/`

先写数据再起服务（`file://` 下 `fetch` 不可用）：

```
python -m counterwrap reduce samples/series/06-gap.csv web/data.jsonl
python -m http.server 8000 --directory web
```

打开 `http://localhost:8000/`。页面读同目录的 `data.jsonl`：上曲线画原始计数、下曲线画增量，异常点按
`kind` 分色并给图例，旁边列出每类异常的条数（取自 `summary` 行），设备可切换（默认第一台）。曲线与
数字只许来自这份数据，页面里不许重算增量或重新归类；不引外部资源。

## 5. 性能与验收口径

规模样例 `samples/series/09-scale.csv.xz`：解压后 1000 万点，100 台设备 × 10 万点。

- 时间：`summary` 端到端（解压、还原、写汇总）≤ 60 秒（Windows + Python 3.13、单进程、单线程）。
- 内存：额外峰值 ≤ 256 MiB（`tracemalloc` 扣基线）且不随总点数增长；不许整份读入，只许按设备块缓冲。

验收逐条：

1. 01–08 的 `reduce` 输出与 `samples/expected/<同名>.jsonl` 逐字节相同（行序、键序、数字写法、结尾换行都算）；
2. `09-scale` 的 `summary` 输出与 `samples/expected/09-scale.summary.jsonl` 逐行相同，且跑在预算内；
3. 同一输入跑两遍，输出逐字节相同；
4. 回绕、复位、突降、乱序各有用例对上，缺失点按 2.3 跳过、零增长不报异常；
5. 页面能打开，两条曲线、异常着色与计数齐全，内容与 `data.jsonl` 一致（人工核对）；
6. 只用标准库、无构建步骤，`python -m unittest discover` 跑通，用例只读 `samples/`。

生成物写 `var/`。

## 6. 样例说明

`samples/series/<名>` 与 `samples/expected/<名>.jsonl` 一一对应、顺序敏感（09 的期望文件叫
`09-scale.summary.jsonl`）：

| 序列 | 覆盖 |
| --- | --- |
| 01-normal | 正常递增、两台设备分组、单步零增长 |
| 02-wrap | 单次回绕：4294967295 → 120，补回跨度 121 |
| 03-wrap2 | 两次回绕，中间夹一次约 42.9 亿的正常上升 |
| 04-restart | 重启归零：3000 → 0 判复位，增量记 0，从 0 继续 |
| 05-unordered | 两台设备各有一条迟到样本，按时刻归位后增量不变 |
| 06-gap | 缺采样：跨 3 小时 29 分与 6 小时的两条增量，不拆不报 |
| 07-zero | 长时间零增长：9 步 0 增量，不报异常 |
| 08-drop | 突降：5400 → 1000 判突降，增量记 0，从 1000 继续 |
| 09-scale | 千万点规模样例（xz），只核汇总：每台 1 次回绕、1 次复位、1 次突降、1 条乱序 |

## 7. 待补的文档

- 旧值也在上半量程的重启与真回绕无法区分，要不要引入速率或时间约束，还是留人工确认。
- 16/64 位计数器与阈值可配置；多设备交错到达（不连续成块）时的流式归并与内存口径。
- 页面配色、长时间轴抽稀，以及 `late` 样本在曲线上的画法。
