# 头部字段解析与规范化（从 0 实现）

仓库里只有本说明、`samples/**` 与 `.gitignore`：库、命令行入口与离线报告都从零写；
`samples/notes.md` 是现场记录，不参与判定。

## 一、范围

交付物（Python 3.13 标准库，无依赖、无构建）：

```text
python -m headfields --headers samples/headers --out var/out
```

默认值就是上例：读 `samples/headers/` 下每一批头部，按第二、三节的口径规范化，在 `--out` 目录写
每批的 `<批次名>.norm.tsv`、`<批次名>.reject.tsv` 和自包含页面 `report.html`。

做：折行与行终止符、字段名大小写归一、重复字段合并、多值拆分、引号与空白规范化、非法字符与长度
判定、确定性输出与离线报告。不做：不解析起始行与消息体（批次文件里只有头部行）；不按字段白名单
区分单值与多值；不解释值的语义（日期、编码参数等）；不按值去重、不做语义等价判断；不做缓存与
历史对比；页面不做编辑与回写；不联网、不引第三方依赖。

## 二、口径与公式

**批次**：`samples/headers/` 下每个不以 `_` 开头的 `*.txt` 是一个批次，批次名是去掉后缀的文件名；
处理顺序按文件名码位升序，与枚举顺序无关。

**行与折行**：文件按 UTF-8 解码（无法解码的字节按非法字符处理）；按 LF 切行，行末紧邻 LF 的一个
CR 属终止符；末尾换行不额外产生一行，最后一行可以没有换行。以 SP 或 HTAB 开头的物理行是**折行**，
接在上一条逻辑行后面：行首连续的 SP/HTAB 换成一个 SP，其余字符原样接上；只含空白的行因此并进上
一条逻辑行。长度为 0 的行不接续，自成一条逻辑行。第一行就是折行时没有可接的对象，该逻辑行报
`E_ORPHAN_FOLD`。

**名称**：逻辑行里**第一个**冒号之前的部分是名称原文（冒号不算）。名称按 Unicode 码位计长，
上限 64；合法字符只有 tchar：``A-Z a-z 0-9 ! # $ % & ' * + - . ^ _ ` | ~``。输出用小写 ASCII。

**值**：冒号之后到行尾是值。合法字符是 SP、HTAB 与可见 ASCII（U+0021..U+007E），其余（C0 控制符、
DEL、非 ASCII、不可解码字节）都算非法字符。空白折叠只作用于引号外：元素内部连续的 SP/HTAB 压成一个
SP，首尾的去掉，引号内的字符（含空白与逗号）原样保留。

**拆分**：按引号外的逗号把值切成元素。引号只能成对地包住整个元素：元素去掉首尾空白后以 `"` 开头的，
必须以 `"` 结尾且内部不再出现 `"`；不以 `"` 开头的，内部不得出现 `"`。规范化后的元素就是去引号、
去首尾空白（引号内不去）、折叠过空白的串；没有转义，`\` 按普通字符处理。

**重复字段**：同一批次里小写后同名的字段合并成一个，值按出现顺序拼接，不去重也不报错；字段在输出
里的位置取**第一次被接受**的那次。

**长度**：值元素按规范化后的串计长，上限 255。

## 三、判定状态机

物理行按顺序进入状态机：当前没有逻辑行时，以 SP/HTAB 开头的行当作（孤儿）逻辑行并继续吸收折行；
其它行结束上一条逻辑行、开始新的一条。每条逻辑行按下序判定，命中一条就停：整行要么被接受、产出
若干值，要么进拒绝清单；被拒绝的逻辑行照样吸收后面的折行，不额外成条。

1. 逻辑行第一条物理行以 SP/HTAB 开头 → `E_ORPHAN_FOLD`
2. 不含冒号 → `E_NO_COLON`
3. 冒号前（名称原文）含 SP/HTAB → `E_SPACE_BEFORE_COLON`
4. 名称为空、含 tchar 之外的字符或长度超过 64 → `E_BAD_NAME`
5. 值含非法字符 → `E_BAD_CHAR`
6. 值去掉首尾空白后为空 → `E_EMPTY_VALUE`
7. 从左到右处理每个元素，按「引号形态 → 去引号后是否为空 → 是否超过 255」判定，
   第一处失败即停：形态不合法 → `E_BAD_QUOTE`，为空 → `E_EMPTY_ELEMENT`，超长 → `E_VALUE_TOO_LONG`

内部状态只有三样：当前逻辑行的行号与拼接文本、按首次出现排序的字段表（字段名 → 值列表）、
拒绝清单（行号、原因码、逻辑行文本）。

## 四、输入输出与文件格式

本节文件一律 UTF-8、LF、无 BOM，末行有换行。退出码：0 = 全部接受，1 = 至少一条拒绝，2 = 用法或
环境错误（`--headers` 不是目录等）；退出码 2 时不写产物，原因写 stderr。

`<批次名>.norm.tsv`：表头 `field	index	value	line`，一行一个值，按字段首次出现顺序、字段内按值
出现顺序。`index` 是值在字段内的序号（从 0 起），`line` 是该值所在逻辑行的第一条物理行号（从 1 起）。
`value` 用 `json.dumps` 默认参数编码：带引号，空白与不可打印字符转义，非 ASCII 也转成 `\uXXXX`。

`<批次名>.reject.tsv`：表头 `line	reason	text`，一行一条拒绝，按行号升序。`reason` 是第三节的原因码，
`text` 是逻辑行文本的 `json.dumps` 编码（折行已按口径拼接，其余原样）。

`report.html`：单文件、无外部资源、不 fetch，双击（`file://`）可开；数据内嵌，覆盖全部批次的结果与
拒绝清单，和两份 TSV 一致；至少能按批次筛选、按字段名搜索，并显示统计。

## 五、性能与验收口径

预算：批次 ≤ 200 个，单文件 ≤ 16 MiB，总物理行 ≤ 200 000；端到端（含页面）≤ 5 秒，
峰值内存 ≤ 256 MiB。

验收：

1. 只用标准库；`python -m headfields --headers samples/headers --out var/out` 在仓库根直接跑通。
2. `var/out/` 下每个 `*.norm.tsv`、`*.reject.tsv` 要和 `samples/expected/` 里的同名文件逐字节相同；
   样例整体返回退出码 1。
3. 同一输入连跑两遍逐字节相同，换 `PYTHONHASHSEED` 也一样；批次顺序不依赖文件系统枚举顺序。
4. `report.html` 离线打开可读，数据与两份 TSV 一致，不出现 TSV 之外的字段或行号。
5. 测试用标准库 `unittest`，只读 `samples/`。

## 六、样例说明

`samples/headers/` 下的八批与 `samples/expected/` 下的十六个同名 TSV 一一对应，逐行比对：

| 批次 | 造出来的场景 | 期望 |
| --- | --- | --- |
| `01-case-and-dupes.txt` | 同一字段三种大小写、一行多个值、逗号后空格数不一、引号里带逗号、值里混 HTAB | 5 字段 10 值，0 拒绝 |
| `02-fold.txt` | 多级折行、折行拼出空格再判名、折行接进引号、被拒行的折行被吸收、首行折行、空白行与空行 | 5 字段 5 值；4 条拒绝（`E_ORPHAN_FOLD`、`E_BAD_CHAR`、`E_SPACE_BEFORE_COLON`、`E_NO_COLON`） |
| `03-quotes.txt` | 合法引号、连续逗号、`""`、未闭合、引号位置不对、引号内的空白与逗号 | 3 字段 6 值；7 条拒绝（4 条 `E_BAD_QUOTE`、3 条 `E_EMPTY_ELEMENT`） |
| `04-structure.txt` | 无冒号、冒号前空白、空名、非 ASCII 名、tchar 全集的合法名、控制符、中文、DEL、坏字节 | 2 字段 2 值；9 条拒绝 |
| `05-limits.txt` | 255/256 边界、引号内超长、多值逐元素限长、名 64/65 边界、空值、空元素、只有逗号 | 3 字段 4 值；8 条拒绝 |
| `06-crlf.txt` | CRLF 终止、行内裸 CR、末行 CR 无 LF | 2 字段 3 值；2 条 `E_BAD_CHAR` |
| `07-rollup.txt` | 400 行滚动数据、40 个名称里三组只差大小写、重复字段与多值、夹杂三种拒绝 | 37 字段 522 值；9 条拒绝 |
| `08-empty.txt` | 0 字节空文件 | 两个文件都只有表头 |
