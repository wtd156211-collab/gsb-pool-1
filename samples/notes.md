# 现场记录（转录，未整理）

- 网关和业务服务都往同一个目录写日志，按天轮转。工作日一天 6~9 个 G，大促能到 12 G，要留 180 天。
- 有人提过「逐行原样入库」，算过账：一天几个 G，一个月上百 G，磁盘、备份窗口、导出全扛不住。而且我们真正要查的往往是「哪几条」，不是「全部几条」。
- 但也不能只留统计。审计和故障复盘经常要求把某一条原始日志一个字不差地拿出来看。上一回工单就是因为抄堆栈时少了一个空格对不上，来回扯了两天。
- 现在查问题靠 grep，一个线上问题在几个 G 里翻，太慢。想要的是：日志照原样落盘，另外生成一份紧凑的「折叠」文件，需要时能把原文还原出来，还原出来跟原文件逐字节一样。
- 折叠出来的东西要能直接看：一眼看出有哪些模板、每个模板出现多少次，最好带一个报表页，浏览器双击就能打开。运维机上什么都不能装，报表页别引外部脚本和样式。
- 环境限制：只允许用 Python 3 自带的库，不让装第三方包，也不让加构建步骤；上线的是断网内网，外链一律打不开。
- 内存不能跟着日志大小涨。之前有个脚本把一天的文件整个读进内存，直接被 OOM 杀了，值班的半夜起来处理。
- 试过按行去重，没用：同一个模板每天几百万行，时间戳、订单号、会话号全不一样，逐行的哈希各不相同。
- 堆栈最烦：一个异常后面跟十几行缩进的调用栈，按行各算各的会把模板数撑上去，希望缩进行能归到上一条记录里。
- 时间上：白天的备份窗口只有十几分钟，折叠必须在这段时间里跑完当天的量。
